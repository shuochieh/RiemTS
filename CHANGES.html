Why

The project consisted of three independent scripts — BWS_util.R, grass_generic_util.R, sphere_generic_util.R — each implementing the same conceptual operations (geodesic distance, exponential/logarithm maps, Fréchet mean, parallel transport, tangent-space bases) for a different manifold: Bures–Wasserstein SPD matrices, the Grassmannian, and the sphere. The math necessarily differs per manifold, but the plumbing around it — dispatch logic for "is this a single point or a batch of points?", the Riemannian gradient-descent loop for the Fréchet mean, and coordinate/basis bookkeeping — was copy-pasted three times with only minor variable-naming differences. The goal was to merge that duplicated plumbing into one generic interface while keeping every existing function callable.

The generic interface

Every manifold now boils down to an object created by a constructor, plus five generic functions that dispatch on it: 

manifold_bws()                  # Bures-Wasserstein SPD manifold
manifold_grassmann(p)           # Grassmannian Gr(d, p)
manifold_sphere()                # unit sphere

geod(mfd, x, y)                  # geodesic distance
Exp_map(mfd, v, mu)              # exponential map
Log_map(mfd, x, mu)              # logarithm map
frechet_mean(mfd, x, ...)        # Riemannian (stochastic) gradient descent mean
parallel_transport(mfd, from, to, v)

Each manifold declares one fact — point_ndim: a BWS/Grassmannian point is a p×p matrix (point_ndim = 2), a sphere point is a length-q vector (point_ndim = 1) — and two shared helpers, map_over_points() and map_over_point_pairs(), use that one fact to handle every combination of "single point" vs. "batch of n points" generically. The manifold-specific math (geod_BWS_core, Exp_gr_core, Log_sphere_core, …) is registered as an S3 method per manifold and stays exactly as specialized as it needs to be — only the dispatch/looping code around it was unified.

coords_from_basis() / tangent_from_coords() replace both coord_gr()/coord2tan() (Grassmannian) and tangent_in_E()/log_to_tangent() (BWS) — these turned out to be the exact same operation (project a tangent matrix onto an orthonormal basis via a 0.5-scaled trace inner product, and reconstruct from coefficients) written twice under different names.

What duplication got removed

Old (3 copies)New (1 copy)What was duplicated
geod_BWS, geod_gr, geod_sphere geod() + map_over_point_pairs() (single,single)/(array,single)/(single,array)/(array,array) branching, differing only in which _core function was called
Exp_BWS/Log_BWS, Exp_gr/Log_gr, Exp_sphere/Log_sphere Exp_map() / Log_map() + map_over_points() "is x a single point or an (n by …) array?" dispatch
mean_on_BWS, mean_on_gr, mean_on_sphere frechet_mean() the entire Riemannian gradient-descent loop (Log → average → Exp step → convergence check), plus unifying batch_size (BWS, absolute count) and batch_por (Grassmannian, fraction) into one parameter
coord_gr/coord2tan, tangent_in_E/log_to_tangent coords_from_basis() / tangent_from_coords() identical trace-inner-product math under different names
Note on the Grassmannian mean. The old mean_on_gr projected each gradient step into basis coordinates before averaging (coord_gr → colMeans → coord2tan), while BWS and the sphere averaged tangent matrices directly. Since coord2tan(coord_gr(X)) is the identity for an orthonormal basis, that detour is mathematically equivalent to a direct average — the new generic frechet_mean() drops it, and tests/smoke_test.R confirms numerically that the two approaches agree.

Backward compatibility

Nothing else in the project (verified against its own backup zip) currently calls the old function names, but they're kept working in R/compat.R as one-line wrappers around the new generic interface, e.g.: 

geod_BWS   = function(X, Y) geod(manifold_bws(), X, Y)
mean_on_gr = function(x, p, tau = 0.1, tol = 1e-8, max.iter = 1000,
                      batch_por = 1.0, init = NULL, verbose = FALSE) {
  frechet_mean(manifold_grassmann(p), x, tau = tau, tol = tol, max.iter = max.iter,
              batch_size = batch_por, init = init, verbose = verbose)
}
pt_sphere  = function(x, y, V) parallel_transport(manifold_sphere(), x, y, V)

BWS-specific higher-level modeling code — rfm_bws, LYB_fm, predict_fm, Frac_Var_bws/Frac_Var_LYB/Frac_Var_ora, dyn_RFM/dyn_LFM, VAR1, project_to_SPD, is.spd, symmetric_to_vector, vector_to_symmetric — isn't part of the cross-manifold duplication problem, so it moved into R/bws_factor_model.R unchanged.

Environment setup

  • Initialized git (git init), committed the original three scripts as a baseline before restructuring.
  • Scaffolded a minimal R package by hand (usethis/devtools weren't installed): DESCRIPTION, R/, man/.
  • Generated NAMESPACE and docs via roxygen2::roxygenise() (already installed).
  • Installed expm, deSolve, maotai from CRAN into the user library — these were already required by the original scripts' library() calls, just never installed in this environment.

The "matches pre-refactor reference" checks run a hand-copied reference implementation of the original mean_on_BWS/mean_on_gr/mean_on_sphere loops (same initial point, no batching, so there's no RNG-driven divergence) and assert numerical agreement with the new frechet_mean() to within 1e-6. A separate, ad hoc check also ran the full rfm_bws() → Frac_Var_bws() pipeline end-to-end on synthetic data.

Known pre-existing gap

dyn_RFM() in R/bws_factor_model.R calls main_BWS(...), which was never defined in any of the original three files. This isn't something the refactor introduced — it was already broken before. Flagging it here in case it should be fixed separately.
